## Последовательность действий

1. Создаем локальную базу данных webflux
2. Актуализируем подключения к БД в application.properties
3. Запускаем Spring Boot приложение, включаем liquibase
4. Проверяем коллекцией в папке postman


## Описание запросов POSTMAN (BLOCKING)

` GET /webflux/customer/7bdd9088-29b2-4fa8-9c3d-bf539ecb825a `

- имитирует синхронный запрос с WEB для получения информации пользователя, который предоставляет сторонний сервис методом callback
- запрос в сторонний сервис не выполняется, но подразумевается что он выполнен, и нам нужно ждать callback с признаком USER_INFO для пользователя, который задан идентификаторов в запросе
- ожидание ограничено параметром TIMEOUT, заданным в конфигурации приложения. Если в течение этого времени (параметр задается в секундах) не будет получен ответ, метод вернет статус 408 и сообщение о произошедшем тайм-ауте
- для ожидания callback - метод с задержкой в 1 секунду (hardcoded) реактивно проверяет БД на существование поступившего ответа от стороннего сервиса
- как только будет найден ответ (раньше чем тайм-аут) - метод вернет информацию пользователя и очистит таблицу БД от прочитанной записи (или записей)

` POST /webflux/customer/callback `

- имитирует callback ответ стороннего сервиса
- этот запрос передает в теле сущность, которую ждет первый метод
- при обработке запроса, в БД делается запись, которую как описано выше ждет синхронный неблокирующий метод GET
- для проверки вы можете сделать сразу несколько callback, чтобы создать несколько записей сразу, и проверить как метод GET выберет для себя только последний и удалит все callback по признаку USER_INFO для заданного пользователя


## Описание запросов POSTMAN (NON-BLOCKING)

` GET /webflux/mono/customer/{user_id} (3 запроса с разными идентификаторами) `

- можно имитировать сразу 3 запроса клиента для получения информации пользователя по разным идентификаторам
- для исполнения запросов выполняется ожидание возвратных запросов от стороннего сервиса
- поэтому чтобы закончить эти методы - выполните соответствующие callback запросы (смотри ниже)

` POST /webflux/mono/customer/callback `

- выполните эти запросы, чтобы завершить запросы клиента описанные выше
